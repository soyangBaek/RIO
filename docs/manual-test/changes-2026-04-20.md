## 1. SFX 볼륨이 시스템 볼륨을 따르지 않던 문제

### 증상
- 라즈베리파이에서 MP3 효과음(댄스/셔터/타이머 알림/스마트홈 성공·실패 등)이 재생될 때 **시스템 볼륨 설정을 무시하고 최대 음량에 가깝게 재생됨**.
- `pactl set-sink-volume`, 블루투스 스피커 볼륨 조절이 앱 출력에 반영되지 않음.

### 원인
- `src/app/adapters/speaker/sfx.py`의 `SFXPlayer._ensure_mixer()`는 `pygame.mixer.init()`을 기본 파라미터로 호출.
- pygame 내부의 SDL은 라즈베리파이에서 기본적으로 **ALSA 드라이버를 직접** 선택 → PulseAudio/PipeWire의 앱별 볼륨 및 기본 sink 볼륨을 **우회**.
- 코드 레벨에서 `sound.set_volume()`을 호출하지 않아 `Sound` 내부 게인은 항상 1.0(최대). MP3 원본 진폭 그대로 ALSA로 직행.

### 수정 내용
- 파일: `src/app/adapters/speaker/sfx.py`
- `_ensure_mixer()`에서 `pygame.mixer.init()` 호출 직전에 `os.environ.setdefault("SDL_AUDIODRIVER", "pulseaudio")` 추가.
- `setdefault`라 외부에서 환경변수로 다른 드라이버(예: `alsa`)를 지정하면 그 값이 우선됨 → 롤백 가능.
- 결과적으로 pygame이 PulseAudio(실제로는 PipeWire의 Pulse 호환 레이어)를 통해 출력 → 시스템/앱별 볼륨이 정상 반영.

### 환경 확인 (수정 전제)
라즈베리파이에 PulseAudio 데몬이 떠 있어야 함.
```bash
pactl info
# Server Name: PulseAudio (on PipeWire 1.2.4)  ← 이런 라인이 보이면 OK
```

## 2. 테스트 절차

### 2-1. 기본 동작 확인 (스트림이 PulseAudio로 흐르는지)
1. 프로그램 실행
2. 효과음이 나는 명령 입력 (예: `춤춰`, `사진`)
3. **재생되는 동안** 다른 터미널에서:
   ```bash
   pactl list sink-inputs short
   ```
4. Python 프로세스 이름의 스트림이 한 줄 이상 보이면 성공.

### 2-2. 앱 스트림 볼륨 조절
1. `춤춰` 입력 (10초 재생되는 동안 여유 있음)
2. 재생 중 스트림 인덱스 확인:
   ```bash
   pactl list sink-inputs short
   # 예: 42    <sink>    <client>    PipeWire-ALSA ...
   ```
3. 볼륨 조절:
   ```bash
   pactl set-sink-input-volume 42 50%
   ```
4. 볼륨이 즉시 낮아지는지 확인.

### 2-3. 기본 sink(스피커) 볼륨 조절
1. 현재 볼륨 확인:
   ```bash
   pactl get-sink-volume @DEFAULT_SINK@
   ```
2. 50%로 설정:
   ```bash
   pactl set-sink-volume @DEFAULT_SINK@ 50%
   ```
3. 효과음 재생해서 전체적으로 낮아지는지 확인.
4. 음소거 토글:
   ```bash
   pactl set-sink-mute @DEFAULT_SINK@ toggle
   ```

### 2-4. 롤백(원복) 테스트
- 직접 ALSA로 돌리고 싶으면 프로세스 실행 전에:
  ```bash
  SDL_AUDIODRIVER=alsa venv/bin/python scripts/live_interaction_test.py
  ```
- 이 경우 수정 전과 동일하게 시스템 볼륨 무시 동작으로 돌아감 (디버깅용).

### 기대 동작
- `pactl list sink-inputs short`에 앱 스트림이 **표시됨** (수정 전에는 표시되지 않았음).
- `pactl set-sink-input-volume`, `pactl set-sink-volume`으로 조절한 값이 실제 출력에 **즉시 반영**.
- 블루투스 스피커 본체 볼륨 버튼도 정상 반영.

## 3. 볼륨 조절 치트시트 (운영용)

```bash
# 기본 sink(기본 출력 장치) 볼륨
pactl get-sink-volume @DEFAULT_SINK@
pactl set-sink-volume @DEFAULT_SINK@ 70%
pactl set-sink-mute   @DEFAULT_SINK@ toggle

# 사용 가능한 sink 목록
pactl list sinks short

# 특정 sink 지정 (예: bluez_output.E2_E5_E4_46_D6_5C.1)
pactl set-sink-volume bluez_output.E2_E5_E4_46_D6_5C.1 70%

# 재생 중인 앱 스트림 조절
pactl list sink-inputs short
pactl set-sink-input-volume <index> 50%
```

볼륨 퍼센트는 `0%` ~ `100%`이 안전 범위. `100%`를 초과 설정하면 클리핑/왜곡 발생 가능.

## 4. 손 흔들기(wave) 제스처 시 welcome 효과음 연발 문제

### 증상
- 사용자가 카메라 앞에서 손을 흔들면 `pleased-emote.mp3`(welcome 효과음)가 **0.75초마다 반복 재생**됨.
- 의도: 한 번만 반갑게 인사하는 것.

### 원인
- `src/app/adapters/vision/gesture_detector.py`의 쿨다운 로직이 두 가지 문제를 가지고 있었음:
  1. `emit_cooldown_seconds = 0.75` — 인사용으로는 너무 짧음.
  2. 손이 프레임에서 잠깐 사라지거나 손가락 형태가 흐트러질 때마다 `_last_gesture = None`으로 리셋 → 손 흔드는 자연스러운 동작("wave 형태 ↔ 아님" 반복) 중에 쿨다운이 매번 **무효화**되어 0.75초마다 재발화.
- `VISION_GESTURE_DETECTED` 이벤트가 reducer에서 `OneshotName.WELCOME`으로 매핑 → `effect_planner`가 `welcome` SFX 계획 → 매번 MP3 재생.

### 수정 내용
- 파일: `src/app/adapters/vision/gesture_detector.py`
- `emit_cooldown_seconds`: `0.75` → **`8.0`초** (기본값)
- `multi_hand_landmarks`가 비어 있을 때 `_last_gesture = None`으로 리셋하던 코드 **제거**
- `gesture`가 None으로 분류될 때 `_last_gesture = None`으로 리셋하던 코드 **제거**
- 결과: 같은 제스처(예: wave)는 마지막 발화로부터 8초가 지나야 재발화. 다른 제스처(예: wave → finger_gun)는 즉시 발화 가능(기존 의도 보존).

### 영향 범위
- `wave`/`peekaboo` → welcome SFX: 최대 8초에 1회
- `finger_gun` → startled SFX: 최대 8초에 1회 (부수 효과, 의도된 개선)
- `v_sign`, `point`: 다른 도메인에서 소비되며 동일한 쿨다운 적용 (명령·UI로 사용 시 8초 간격 필요 — 필요 시 per-gesture 쿨다운으로 분리 가능)

### 테스트 절차
1. 프로그램 실행 (카메라 연결 필수)
2. 카메라 앞에서 손을 5~10초간 흔들기
3. **welcome SFX가 한 번만 재생**되는지 확인 (수정 전: 여러 번 연발)
4. 8초 이상 대기 후 다시 손 흔들기 → 재생되는지 확인
5. 중간에 다른 제스처(예: 손가락총)를 만들면 즉시 startled가 발화하는지 확인

### 기대 동작
- 한 번의 손 흔들기 세션에서 `pleased-emote.mp3`가 **1회만** 재생
- 8초 쿨다운 이후 다시 흔들면 다시 1회 재생
- 다른 종류 제스처 전환 시 해당 SFX는 정상 즉시 반응

## 5. 알려진 이슈 / 주의사항

| 이슈 | 영향 | 대응 |
|------|------|------|
| PulseAudio/PipeWire 미기동 환경 | 효과음 재생 실패 가능 | `SDL_AUDIODRIVER=alsa`로 임시 롤백 |
| 블루투스 스피커 재연결 시 기본 sink 변경됨 | 볼륨 조절 대상이 바뀔 수 있음 | `@DEFAULT_SINK@` 대신 명시적 sink 이름 사용 |
| 프로세스별 코드 레벨 볼륨 | 현재 적용 없음 | 필요 시 `robot.yaml`에 `sfx_volume` 필드 추가 후 `Sound.set_volume()` 연동 가능 |
